# i-app-emulator-in-browser

iアプリ（DoJa）をブラウザで動かすための実験的なエミュレーターです。
FreeJ2ME-Plus を基盤とし、CheerpJ 上で実行します。任意で openDoJa 由来の
ソフトウェア OpenGL ES 描画を使用できます。

**ゲーム本体・端末ダンプ・復元した保存データ・ゲーム素材は含みません。**
利用者が手元の JAR / JAM / SP をファイル選択で読み込む方式です。
互換性は限定的で、すべての iアプリの動作を保証するものではありません。

## 公開版

<https://i-appli.simeis512.com/>

ビルドせずにそのまま利用できます。`main` の検証がすべて成功したときに自動更新します。
この配布版に対応するソースは [source.zip](https://i-appli.simeis512.com/source.zip) から取得できます。

保存データは接続先のホスト名ごとに分かれます。別のURLで開くと保存は引き継がれないため、
このURLを使用してください。手元でビルドして動かす場合は次の手順です。

## 起動

ビルドには **JDK 17 以上**（`java` と `javac`）、**Python 3.10 以上**が必要です。
通常実行に Node.js は不要です。ビルド用の依存 Java ソースは同梱しています。
ビルドは外部ライブラリをダウンロードしません。

```sh
git clone https://github.com/simeis512/i-app-emulator-in-browser.git
cd i-app-emulator-in-browser
python build.py
python build_ogl.py
python serve.py
```

`http://127.0.0.1:9052/` を開きます。Windows ではビルド後に
`Start-Emulator.cmd` で起動、`Stop-Emulator.cmd` でローカルサーバーを停止できます。
Python が PATH にない場合は `Start-Emulator.ps1 -PythonExe "Pythonのパス"` を使用します。
macOS / Linux では環境に応じて `python` を `python3` に読み替えてください。

ブラウザでの実行には CheerpJ の公式 CDN への接続が必要です。
初回起動は時間がかかります。`index.html` を直接開く `file://` 起動には対応しません。
動作検証は Windows の Chromium 系ブラウザで行っています。

### Windowsで `javac` が見つからない場合

`build.py` で `FileNotFoundError: [WinError 2]` が出て、失敗した行が `javac` の実行なら、
Javaコンパイラが見つかっていません。**JDK 17以上**を導入してください。Java実行環境（JRE）だけではビルドできません。
例として [Microsoft Build of OpenJDK の公式手順](https://learn.microsoft.com/ja-jp/java/openjdk/install) に従い、
PowerShellからインストールできます。

```powershell
winget install --id Microsoft.OpenJDK.17 --exact
```

インストール後はPowerShellを開き直し、`javac -version` が17以上を表示することを確認します。
既にJDKがある場合は、`JAVA_HOME` にそのJDKのフォルダー（`bin` の1つ上）を設定してもビルドできます。
ビルドスクリプトは `JAVA_HOME` を優先し、未設定ならPATHから `javac` を探します。

### 更新・別PCへのコピー

**`git pull` や `python serve.py` はJavaをビルドしません。** ソース更新後は次の順に実行し、
各ビルドの成功を確認してからブラウザを再読み込みしてください。

```powershell
git pull
python build.py
if ($LASTEXITCODE -ne 0) { throw 'コアのビルドに失敗しました' }
python build_ogl.py
if ($LASTEXITCODE -ne 0) { throw '3Dのビルドに失敗しました' }
python serve.py
```

ビルドしたJARにはソースの内容に基づく識別情報が入ります。新しい `serve.py` は現在のソースと照合し、
古いJAR・識別情報のない旧版はブラウザでの起動時に再ビルドを案内します。別PCへのコピー日時には依存しません。
`serve.py` 自体を更新した場合はサーバーも再起動してください。一般の静的サーバーにはこの照合機能はありません。

別PCでビルドせずに使う場合は、ビルド済みの配布ZIPを**フォルダー全体として**コピー・展開してください。
このZIPは `python package.py`、または GitHub Actions の成功した実行の `emulator-with-source` Artifactから取得できます。
配布ZIPにはJava実行ファイル・対応ソースが含まれ、起動先PCのJDKは不要です（Pythonとブラウザは必要）。
コピーした配布物に `git pull` のソースを重ねる場合は、その後の再ビルドが必要です。

## アプリを読み込む

1. 対応する **JAR と JAM** を選びます。SP がある場合は一緒に選ぶか、後から追加します。
2. 画面サイズを選びます。描画モードは通常「自動判別」のままで構いません。起動時に JAR を調べ、
   OpenGL ES を使うアプリは 3D、それ以外は 2D で起動します。判別できない場合は 2D で起動して
   その旨を表示するので、3D のアプリなら「OpenGL ES / 3D」を手動で選んでください。
3. 「起動する」を押します。

「音声（試験中）」と音量スライダーで音を調整できます。初期音量は 30% です。
「PCM音量（効果音など）」では、BGMなどの合成音に対するPCMの音量を調整できます。
合成音よりPCM効果音が大きく聞こえるため、初期値を 25% にしています。100% が従来の音量です。
アプリ側の音量指定も引き続き反映されます。PCMを使うBGMにも適用され、MIDIの効果音は対象外です。
再生中も変更できます。端末の正確な音量比を再現した値ではなく、設定は再読み込みで初期値に戻ります。
**他のタブへ移ったときや画面を消したときは音を止めます。** 戻ると再開します。
MLD / MIDI は標準では独自の簡易合成音源で鳴らすため、端末の音色とは異なります。
外部の SoundFont や音源 ROM は必要ありません。音が出ない場合は音声のチェックを入れ直してください。

### 外部の音色を使う（任意・試験中）

音声欄の「外部の音色を使う」を開き、手元の音色ファイルを選択できます。
現在の対応形式は **openDoJa の FueTrek 音色ファイル `fuetrek-rom.bin`（FTRM v1）**です。
[openDoJa](https://github.com/GrenderG/openDoJa) のコミット
`0eb46a3905733458d1f7ded49cd1ba8dcc93511f` で使われている形式をローカル検証しています。
利用権限のあるファイルを別途用意してください。音色データの配布・自動取得は行いません。

選択したファイルから楽器・打楽器の波形、音域、チューニング、ループ、2つの波形の混合比と
音量エンベロープ情報を読み込み、Web Audio で近似再生します。
MLD から変換した General MIDI の楽器番号に合わせて音色を選びます。
未収録の音色や非対応のネイティブノイズ生成音色は、標準の簡易音源で補います。
アプリ内の PCM 効果音は、外部音色を選んでも引き続きアプリのデータから再生します。

これは **openDoJa / FueTrek の音源エンジン全体の移植ではありません**。
独自のバンク切り替え、音色編集命令、音質加工、ネイティブの補間・変調・ミキサーの完全再現は未対応です。
エンベロープも近似で、P905i や openDoJa と同じ音になる保証はありません。
`fuetrek-control.bin` などの補助ファイル、MA-3 の音色ファイル、SoundFont（SF2/SF3）、
DLL、任意の端末 ROM は読み込めません。対応ファイルの上限は 16 MiB です。

選択はそのページ内だけで有効で、サーバーへのアップロードやブラウザへの永続保存は行いません。
曲の途中でも選択・解除でき、「標準の音色に戻す」で簡易音源に戻ります。
読み込みに失敗した場合は、それまでの音色を継続します。ページを再読み込みすると標準に戻ります。
音色切り替えでは現在位置で発音を作り直すため、短い音の途切れやアタックの再発音があり得ます。

### JAM・SP の扱い

JAM は Shift_JIS として読み、`AppClass` と `SPsize` を使用します。
JAR / JAM は必須です。JAR だけからの設定推測、ZIP 一括読み込み、端末ダンプの解析・復号は行いません。
JAR / SP は約 64 MiB、JAM は 256 KiB、スクラッチパッドは合計 64 MiB・16 領域までです。
ファイル名の大文字・小文字やベース名の一致は問いません。

SP は JAM の `SPsize` を合計した長さの生データ、または 64 バイトヘッダー付きの形式を扱います。
SP を省略すると空の領域を作成します。SP に追加の画像・音楽などを保持するアプリは、
空の領域では起動できないことがあります。別アプリの SP を組み合わせないでください。

| 操作 | キー |
| --- | --- |
| 方向 | 矢印キー |
| 決定 | Enter / Space |
| 左・右ソフトキー | Z / X |
| テンキー | 0〜9、`*`、`#` |
| クリア | BackSpace |

画面上のボタンでも操作できます。方向キーは端末と同じ輪の形で、**外周を押すとその向き、
斜めを押すと縦横の2方向が同時に入ります。** 押したまま指を動かすと向きが変わります。
中央は決定キーです。横持ちアプリではキーの方向が異なる場合があります。
アプリ切り替え・再起動はページを再読み込みして、ファイルを選び直します。

アプリが指定したソフトキーの説明は、端末と同じように**画面の下**に表示します。
アプリ側の描画には重ねません。アプリが表示しない設定にした場合は隠します。

クリアキーは押下・解放のイベントとしてアプリへ届きます。DoJa のキー押下状態は 32 ビットで、
クリアキーの番号を表現できないため、押下状態の問い合わせでは報告されません。

### スマートフォン

画面とキーパッドが 1 画面に収まる**プレイ表示**があり、スクロールせずに画面を見ながら操作できます。
右上のボタンで**どの端末・どのブラウザでも切り替えられます**。タッチ操作の端末では起動時に
自動でこの表示になりますが、切り替えは常に手動で行えます。

プレイ表示では**画面とキーパッドを上下に分け**、間の仕切りを上下にドラッグすると配分を変えられます
（仕切りを選んで上下の矢印キーでも変えられます）。画面もキーパッドも縦横比はそのままで、
与えられた領域いっぱいに拡大します。配分はこのブラウザに保持します。

キーパッドは端末と同じ縦並びを基本としますが、横長で高さの足りない領域ではキーが小さくなりすぎるため、
その場合だけ方向キー側と数字側を横に並べます。キーの意味と位置関係は変わりません。

「キー非表示」で画面上のキーパッドを隠せます。キーボードやゲームパッドで操作する場合に、
画面を広く使えます。この選択はこのブラウザに保持します。

「全画面」で、ブラウザの上下のバーを隠せます。横持ちでは表示領域がかなり広がります。
対応していないブラウザ（iOS の Safari など）ではボタンを表示しません。

画面上のキー・キーボード・ゲームパッドでキーを押すと、短い振動を要求します。
**アプリが指示する振動**も同じ設定を使い、画面の再描画を待たずに伝えます。
対応する端末・ゲームパッドの両方が対象です。「振動でキーの手応えを返す」で切り替えます。
キーの手応えがアプリの連続振動を短く切ることはありません。ページが非表示の間は停止します。

「振動を試す（0.2秒）」はアプリを起動せずに使えます。端末とゲームパッドそれぞれの
受付結果・非対応・エラーを表示します。ただし **要求の受付は、実際の振動の確認ではありません**。
ブラウザからモーターの有無や動作は検出できません。Androidの対応ブラウザでも、端末の振動・
サイレント設定などにより振動しない場合があります。iOSのSafariなど端末の振動APIに未対応の
ブラウザでは動作しません（[Vibration APIの実装状況と制約](https://www.w3.org/TR/vibration/)）。

アプリの要求は実行ログの `Application vibrator on/off` で確認できます。記録があっても
ブラウザ側で拒否されたり、端末側で振動しなかったりするため、上のテストと併せて確認してください。

**振動しない場合は、まず端末の「通知をミュート」やおやすみモードが有効になっていないか確認してください。**
Android ではこれらが有効だと振動が止まりますが、ブラウザは要求を受け付けたと返すため、
ページ側からは原因を判別できません。「振動を試す」が受付済みと表示するのに振動しないときは、この設定が原因の可能性が高いです。

端末の向きによらず画面の下にキーパッドが並び、どちらの向きでもスクロールは不要です。

### 横持ちアプリ

画面を回して本体ごと横に持つ端末に合わせて、「キーパッドの向き」で
**キーパッド全体を左右どちらかに倒せます。** 数字の並び・ソフトキーとクリアキーの位置・
方向キーが送る向きが、まとめて回ります。例えば左に倒すと数字は次の並びになり、
方向キーの左を押すと上方向が入ります。

```
3 6 9 #
2 5 8 0
1 4 7 *
```

キーの刻印も端末と同じように横倒しになり、**キー自体も縦長になります**（端末のキーは横長のため）。
方向キーの矢印は外向きのまま変わりません。
端末を回しても矢印は一緒に回るため見た目は同じで、各位置が送るキーだけが入れ替わります。

どちらに倒すかはアプリによって異なるため、自動では切り替えません。選択はこのブラウザに保持します。

### ゲームパッド

標準配置のゲームパッドに対応します。十字キーと左スティックが方向、A が決定、B がクリア、
X・Y が左右ソフトキー、L・R が `*`・`#`、Select・Start が 1・3 です。
「ゲームパッド」欄の「割り当てを変更」で、押したボタンを順に割り当て直せます。
割り当てはこのブラウザに保持し、「標準に戻す」で初期値へ戻せます。
接続が切れたときとタブを離れたときは、押されたままのキーを解除します。

## 保存とファイルの扱い

- 読み込んだ JAR / JAM / SP はブラウザ内の実行環境へ渡します。ファイルをサーバーへアップロードする機能はありません。
- 保存は CheerpJ の `/files`（ブラウザの IndexedDB）に保持します。JAR と JAM の内容の SHA-256 を組み合わせてアプリを識別します。
- **同じアプリの保存が既にある場合、選択した SP よりブラウザ内の保存を優先します。** SP の再選択で保存を上書きする機能はありません。
- 「SPを書き出す」で現在のスクラッチパッドを連結したヘッダーなし SP を保存できます。元の入力ファイルは変更しません。
- ブラウザ・プロファイル・接続先のホスト名やポートが変わると保存領域が変わります。サイトデータ削除やプライベートモード終了で失われる場合があるため、必要な SP は書き出してください。
- SP 書き出しはスクラッチパッドのみです。端末状態や任意の Java ファイル・RMS 全体を移行するものではありません。アプリが保存した後に書き出してください。

Java コードを実行するため、信頼できるアプリを使用してください。保存先の分離は整理のためで、
アプリ同士を隔離するセキュリティ境界ではありません。ホスティング時は専用のオリジンを使用してください。
CheerpJ の取得には外部通信が発生します。アプリ向け通信 API の非対応は、ネットワーク遮断を保証するものではありません。

## 現在の対応範囲

| 項目 | 状態 |
| --- | --- |
| DoJa の起動・Canvas・キー入力 | 一部対応。DoJa 5.1 設定で動作 |
| 文字の描画 | 端末と同じくアンチエイリアスなしで描画。TINY〜LARGE の指定を反映。**大きさは P905i の実機と一致していない**（下記） |
| 操作手段 | 画面のキーパッド（斜め入力対応の方向ダイヤル）、キーボード、標準配置のゲームパッド（割り当て変更可） |
| ソフトキーの説明 | アプリが指定した文字列を画面の下に表示 |
| 振動 | キー操作の手応えと、アプリが指示する振動（対応端末のみ） |
| 横持ちアプリ | キーパッド全体を左右に倒せる（配置とキーの向きが連動） |
| プレイ表示の配分 | 画面とキーパッドの上下配分をドラッグで調整 |
| スマートフォン表示 | 画面とキーパッドを 1 画面に収める表示に対応 |
| スクラッチパッド | 生 SP / ヘッダー付き SP、ブラウザ保存、SP 書き出し |
| 音楽イベント | テンポを反映した時計、同期・終了通知、停止・再開・シーク、全曲ループ |
| MLD / MIDI 音声 | Web Audio による簡易合成。プログラム変更、音量・パン・サステイン・ピッチベンド幅・簡易ビブラート |
| 外部の楽器音色 | ユーザーが選択した FueTrek FTRM v1 波形バンクの近似再生。標準は簡易合成 |
| PCM 音声 | PCM WAVE、MLD 内の一部 2 bit / 4 bit ADPCM の再生・停止 |
| OpenGL ES | 実験的なソフトウェア描画。色マスク・三角形のフォグなどを実装 |
| 多重テクスチャ・反射・拡張 API | 制限あり。未対応処理はログまたは例外で通知 |
| 通信・認証・配信サーバー依存 | 未対応 |
| 端末固有機能・iアプリDX・完全な MIDP 互換 | 検証・実装は不十分 |

**文字の大きさは実機と一致していません。** アプリが指定する TINY・SMALL・MEDIUM・LARGE は区別して描きますが、
各サイズの寸法は P905i の実機で確認できていないため、実機より大きく描かれる場合があります。
画面に合わせて改行された文章が、枠や画面の端からはみ出すことがあります。

3D は低速です。2D は Java 8、3D は Java 17 の CheerpJ 環境を使用します。
「OpenGL ES / 3D・WebGL2（試験中）」は、3D の画素を GPU（WebGL2）で描く開発中の方式です。今は色付きの三角形と深度テストを描き、
テクスチャ・半透明などは未対応で、その旨を実行ログに表示します。WebGL2 を使えないブラウザでは通常の 3D で動きます。
Java の版は 1 ページで 1 回しか選べないため、描画モードを変えるときはページを再読み込みします。
JavaScript から Java へのキー入力・状態取得・保存処理は共通の待ち行列で実行します。
本リポジトリで再現できるブラウザテストは、独自作成の小さなテストアプリによるものです。
商用ゲームをテストや配布物に含めていません。

音声は試験的な実装です。端末の音源・音色・エフェクトの完全再現、SMAF/MP3/AMR、
MLD 内部の特殊ループや全拡張には対応していません。通常の MIDI 打楽器は手続き的に合成します。
DoJa の同期用に指定された音符は発音せず、ゲームへの同期イベントに使用します。
曲が指定するピッチベンド幅（RPN 0）を反映します。モジュレーション（CC1）は
簡易音源用のビブラートで近似しており、端末固有の FM 音源やエフェクトの再現ではありません。
PCM は非圧縮整数 8/16/24/32 bit と float32 WAVE を扱い、音声ストリームは 16 MiB までです。
MLD 内の 2 / 4 bit ADPCM は openDoJa の復号処理を使用し、8 / 16 kHz・モノラルの
対応形式（selector `0x81`、mode `1`）を 32 kHz PCM として再生します。
MLD 内の非圧縮 PCM16（selector `0x80`、mode `1`）も対応しています。
未対応形式はログに出し、後続の効果音の番号がずれないように扱います。復号後も 16 MiB が上限です。
SH 形式の Wave Packet Data / Data3（`0x71 0x83` / `0x71 0x84`）に入った
単発の ADPCM 効果音も再生します。8 / 16 kHz・2 / 4 bit・モノラルで、
1パケットに完結する即時再生（SET）と初期音量に対応しています。外部音色は不要です。
分割パケット、保存後の再利用、32 kHz、再生途中のPCM音量変更・パンは未対応で、実行ログに記録します。
太鼓の達人の別音色など、ADAT チャンクを使わず波形命令に音声を格納する効果音が対象です。
NEC形式のストリーム波形登録（`11 01 F0 07`）と再生（`11 01 F1 03`）にも対応します。
対象はモノラル・format 1・4〜16 kHz の Yamaha ADPCM です。既存デコーダーによる近似再生で、
ステレオ、その他の形式・制御命令、MA-3 の FM音色合成は未対応です。音色バンクは不要です。
ゲームが指定するテンポ変更では、MIDI の音程を維持し、PCM は再生速度と音程が同時に変わります。
リズムゲームの発音遅延・判定の実機一致は未検証です。タブの休止や高負荷時には音切れが発生し得ます。

## テスト

ビルド後に実行します。Node.js 20 以上が必要です。

```sh
python dependencies.py
python notices.py --check
python check.py
python -m unittest discover -s tests -p "test_*.py"
npm test
python public_audit.py
```

任意のブラウザ統合テスト（CDN 接続が必要）:

```sh
python tests/build_fixture.py
npm ci
npx playwright install chromium
python serve.py
# 別のターミナルで
npm run test:browser
npm run test:audio
```

`tests/TestIappli.java` は本プロジェクト独自のテストコードです。
生成した JAR / JAM / SP は `build/fixture/` に置かれ、Git や配布 ZIP には入りません。
ブラウザテストは別プロファイルで描画・入力・SP ダウンロード・保存復元・Java 17 起動に加え、
Java のメディア API から実際に波形が出ること、音量・PCM 効果音・停止・再開・消音を確認します。
2 bit ADPCM を含む自作 MLD でも、発音・連続再生・音の終了を確認します。
SH 波形命令の自作 MLD では、BGMを消して発音・連打・停止／再開を検証します。
`test:audio` は CheerpJ の CDN 通信を遮断し、独自のテスト音を OfflineAudioContext でレンダリングして
周波数・発音終了・サステイン・シーク・テンポ・同期音符の除外・ピッチベンド幅・ビブラートを確認します。
外部音色のパーサーと波形テストには、数学的に生成した正弦波だけの独自フィクスチャを使います。
プログラム選択・移調・ループ・打楽器・標準音源への復帰と、壊れた入力の拒否も検証します。
第三者の音色バンクはリポジトリ、CI、配布 ZIP に含めません。
`TEST_URL` で接続先、`BROWSER_CHANNEL=msedge` などで既存ブラウザを指定できます。

利用・公開の際は [CheerpJ の現在の利用条件](https://cheerpj.com/docs/licensing)を確認してください。

```sh
python package.py
```

公開対象の許可リストと依存ソースを検査し、両 JAR を再ビルドして
`dist/i-app-emulator-in-browser.zip` を作成します。
ZIP にはビルドスクリプト・依存ソース・ライセンスを含め、`web/source.zip` から
その配布版に対応するソースを取得できるようにします。ゲームや個人の保存は含みません。
`public_audit.py --tracked` は Git の登録対象も許可リストと照合します。

静的サイトとして配布する場合は ZIP 内の **`web/` 全体**を HTTPS で配置し、
`source.zip` も同じ場所で取得できるようにしてください。
**HTTP Range リクエストへの対応は必須です。** CheerpJ は JAR を分割して取得するため、
Range に対応しないホスト（Python 標準の `http.server` など）では動作しません。
`.jar` に圧縮を掛けるホストも Range を無効化することがあります。
**ページと、そのページが読み込むファイルは同じ頻度で再検証されるようにしてください。**
ファイル名に内容のハッシュを付けていないため、HTML だけが新しく JavaScript や CSS が古いままだと、
画面が崩れたり実行時にメソッドが見つからなくなったりします。同梱の `web/_headers` は
Cloudflare Pages 向けの指定です。**CDN やゾーン側の設定がこれを上書きすることがあります**
（Cloudflare では「Browser Cache TTL」を Respect Existing Headers にするか、
対象ホスト向けの Cache Rule を用意してください）。

`python verify_site.py <URL>` で、配置したサイトがこれらの条件を満たすか確認できます。
配布 ZIP の `SHA256SUMS.json` を `--sums` に渡すと、そのビルドが実際に配信されているかも照合します。

このリポジトリの CI は、`main` の検証がすべて成功したときに上記の `web/` を公開先へ配信し、
同じ検証を公開 URL に対して実行します。

## 構成

- `src/` — ブラウザ橋渡し、音楽イベントの時計と音声出力への接続
- `src-ogl/` — フォグ補助処理
- `web/` — ファイル選択・描画・操作 UI、Web Audio の簡易音源と PCM 再生
- `build.py` / `build_ogl.py` — 原本を変更せず、ビルド用コピーに修正を適用
- `vendor/` / `UPSTREAM.json` — 固定した上流ソースとハッシュ
- `tests/` — 自作データだけで動作する検証
